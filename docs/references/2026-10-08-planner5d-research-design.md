집 도면을 바탕으로 가구를 배치하고 인테리어를 결정하는 개인용 앱의 기초 설계안이다. Planner 5D 공식 도움말과 공개 사용자 후기를 참고해 사용 흐름, 설계 요구사항, 초기 개발 범위를 정리했다.

**추천 방향은 실제 치수로 방을 만들고, 가구가 들어가는지 확인하고, 배치안 두 개를 비교하는 앱이다.** 첫 100시간에는 방 하나의 작업을 끝까지 완성한다. 자동 도면 인식과 집 전체 편집은 후속 단계로 둔다.

작성 기준일은 2026년 10월 8일이다. 제품 기능은 공식 문서에 근거하며, 후기는 개별 사용자의 경험으로 다룬다. 아래의 제품 제안, 구현 방식, 일정, 가격은 검증 전 가설이다. 이번 조사는 문서와 공개 후기 조사이며 앱을 직접 조작한 사용성 시험은 수행하지 않았다.

## 2 Planner 5D 공식 사용 흐름

### 직접 방을 만드는 경로

| 단계 | 공식 문서에서 확인한 조작 | 벤치마킹할 지점 |
| - | - | - |
| 방 생성 | 웹에서는 Build에서 기본 방 모양 또는 그리기 도구를 선택한다. iOS에서도 모양 선택과 직접 그리기를 지원한다 | 처음부터 모든 도구를 보여주기보다 방 만들기로 시작 |
| 치수 입력 | 벽을 선택해 길이를 숫자로 입력하거나 드래그한다. 웹에서는 벽 두께도 조절한다 | 드래그와 숫자 입력을 함께 제공 |
| 방 연결 | 방을 각각 만든 뒤 나란히 배치하도록 안내한다 | 방과 벽의 연결 규칙을 사용자에게 예측 가능하게 설명 |
| 문과 창 추가 | 방을 만든 다음 문과 창을 추가하고 인테리어 단계로 이동한다 | 구조와 장식 단계를 분리 |
| 가구 배치 | 카탈로그의 물체를 프로젝트에 놓고 선택한다 | 선택한 물체의 크기와 위치를 바로 확인 |
| 가구 치수 수정 | iOS 도움말 기준 물체 선택 → Edit → Size → 수치 입력. 일부 물체의 크기를 변경할 수 있다 | 치수 편집을 찾기 쉬운 위치에 배치 |

방 생성과 벽 편집은 [공식 방 추가 도움말](https://support.planner5d.com/en/articles/16902413-how-to-add-a-room), 물체 치수 편집은 [공식 물체 높이 조절 도움말](https://support.planner5d.com/en/articles/7870489-adjusting-object-heights)에 근거한다. 물체 편집 문서는 2023년 작성 자료이므로 실제 앱의 버튼 위치는 확인이 필요하다.

### 기존 도면을 가져오는 경로

웹에서는 My spaces → My Space → Dashboard → Import a Plan으로 진행한다. PDF에 여러 페이지가 있으면 평면도 페이지를 선택하고 층을 지정한 뒤 인식을 시작한다. iOS에서는 Create Project → Upload a floor plan → 사진 또는 파일 선택 → 인식 완료 후 수정하는 흐름이다.

공식 도움말은 JPG, PNG, PDF, DWG 등을 지원하며 유료 기능이라고 안내한다. 도면에는 치수가 있어야 하고, 고대비의 평면도와 한 층씩 구분된 자료가 적합하다. 원근이 있는 사진이나 입면도는 적합하지 않다. 인식 후 누락된 벽이나 치수는 수동 보정할 수 있다. [공식 도면 업로드 도움말](https://support.planner5d.com/en/articles/14434484-how-to-upload-a-floor-plan)

가격 페이지는 즉시 변환을 홍보하지만, 상세 도움말은 인식에 통상 10분에서 24시간이 걸릴 수 있다고 설명한다. 따라서 새 앱의 자동 인식 기능도 실제 지연을 측정한 뒤 처리 상태와 보정 경로를 설계해야 한다. [가격 페이지](https://planner5d.com/pricing), [도면 처리 시간 안내](https://support.planner5d.com/en/articles/14434484-how-to-upload-a-floor-plan)

### 3D 확인과 저장 및 공유

웹 3D 화면은 왼쪽 드래그로 시점 회전, 오른쪽 드래그로 이동, 휠로 확대를 지원한다. WASD 이동과 카메라 높이 설정도 제공한다. 모바일 조작을 이 방식과 같다고 가정하지 않는다. [공식 웹 3D 조작 안내](https://support.planner5d.com/en/articles/13161059-3d-navigation-and-camera-controls-web)

프로젝트는 로그인과 인터넷 연결이 있을 때 자동 저장된다. 공식 안내는 오프라인 변경이 동기화되기 전에 다른 기기에서 열면 미저장 변경을 덮어쓸 수 있다고 명시한다. 저장 상태와 기기 간 충돌 처리는 새 앱에서도 중요한 요구사항이다. [공식 저장 안내](https://support.planner5d.com/en/articles/15156440-how-to-save-projects)

프로젝트에서 Share를 선택해 링크를 복사하거나 전송할 수 있다. 기본 보기 공유와 웹의 실시간 공동 편집을 구분해서 확인해야 한다. 공유 도움말 안에도 편집 권한 안내가 혼재되어 있어 플랫폼별 실제 동작을 확인할 항목으로 남긴다. [공식 공유 안내](https://support.planner5d.com/en/articles/15116256-how-to-share-projects)

## 5 MVP 범위와 사용자 흐름

### 첫 100시간의 범위

**P0는 필수, P1은 다음 단계, P2는 확장 기능이다.** P0는 단층의 직사각형 방 하나를 대상으로 한다. L자 방은 다음 단계로 확장한다.

| 우선순위 | 기능 |
| - | - |
| P0 | JPG·PNG 배경 도면, 알려진 길이를 이용한 축척 설정 |
| P0 | 직사각형 방 생성, 내측 치수 입력, 벽 두께·높이 입력 |
| P0 | 문·창 배치, 폭·높이·벽 시작점으로부터 거리 입력 |
| P0 | 기본 가구 생성, 치수 입력, 이동·회전·복제·삭제 |
| P0 | 동일 데이터에서 2D·3D 표시, 카메라 초기화 |
| P0 | 선택한 가구와 벽 사이 거리, 단순 겹침과 문 여는 영역 표시 |
| P0 | 구조를 공유하는 A/B 배치안, 자동 임시 저장, 불러오기 |
| P0 | 현재 배치의 2D·3D 이미지 내보내기 |

원본이 PDF인 경우 초기에는 평면도 페이지를 이미지로 변환해서 사용한다. PDF 입력이 실제 사용자에게 필수라는 것이 확인되면 P0로 올리고 L자 편집 등 다른 항목의 일정을 조정한다.

### 끝까지 이어지는 기본 흐름

1. 새 프로젝트에서 도면 이미지 또는 기본 방 모양을 선택한다.

2. 도면 위 두 점을 찍고 알려진 실제 길이를 입력한다.

3. 방 외곽을 만들고 내측 치수를 실측값과 비교한다.

4. 문·창의 위치와 크기를 입력한다.

5. 실제 가구 치수를 입력하고 2D에서 배치한다.

6. 거리와 문 여는 영역을 확인한다.

7. 3D에서 공간감을 확인한다.

8. A안을 복제해 B안을 만들고 같은 시점에서 비교한다.

9. 저장 상태를 확인하고 결과 이미지를 내보낸다.

도면에 실제 길이가 없으면 축척을 확정하지 않는다. 사용자가 입력한 방 크기로 임시 모델을 만들되, 미확인 치수가 있음을 화면과 내보내기에 표시한다.

### 오류와 중단 상태

- 축척 미설정: 거리 측정을 활성화하기 전에 길이 입력을 안내한다.

- 왜곡된 도면: 첫 기준 길이 외에 다른 방향의 실측 길이로도 확인한다. 차이가 크면 정확한 배경 정렬을 주장하지 않는다.

- 닫히지 않거나 교차한 방 외곽: 문제가 있는 점을 표시하고 수정 전 3D 생성을 보류한다.

- 문이 벽 끝을 벗어남: 허용 범위를 보여주고 마지막 유효 위치를 유지한다.

- 편집 오류: 직전 상태로 되돌리며 가구와 치수를 임의로 삭제하지 않는다.

- 저장 실패: 작업 화면을 유지하고 로컬 파일 내보내기 경로를 제공한다.

## 6 화면과 조작 설계

| 화면 | 주요 정보 | 핵심 행동 |
| - | - | - |
| 프로젝트 목록 | 이름, 최근 수정 시각, 저장 위치 | 새 프로젝트, 다시 열기 |
| 도면 준비 | 원본 이미지, 축척, 기준 길이 | 두 점 선택, 길이 입력, 원본 잠금 |
| 2D 편집 | 방, 치수, 가구, 문 여는 영역 | 구조 편집, 가구 배치, 거리 확인 |
| 선택 속성 | 이름, 크기, 위치, 회전, 확인 여부 | 숫자 입력, 복제, 잠금, 삭제 |
| 3D 보기 | 같은 배치의 입체 표현 | 회전, 이동, 확대, 시점 초기화 |
| 배치안 비교 | A/B 이름, 메모, 같은 카메라 위치 | 전환, 차이 확인, 이미지 저장 |

PC에서는 중앙 캔버스, 왼쪽 도구·가구 목록, 오른쪽 선택 속성을 제안한다. 모바일에서는 캔버스와 하단 속성 패널을 사용하며 패널이 선택한 가구를 가리지 않게 한다.

조작 원칙은 다음과 같다.

- 카메라 이동과 가구 이동을 명확히 구분한다.

- 스냅은 현재 상태를 표시하고 끌 수 있게 한다.

- 겹친 물체는 선택 후보 목록으로 고를 수 있게 한다.

- 숫자 입력 옆에 단위를 항상 표시한다.

- 90도 회전과 시점 초기화 버튼을 눈에 띄게 둔다.

- 실행 취소는 구조 편집과 가구 편집 모두에 적용한다.

- 모바일 편집을 출시 범위에 포함하면 한 손가락 선택·이동, 두 손가락 화면 이동·확대의 충돌을 실제 기기에서 검증한다.

## 7 요구사항과 완료 기준

이 절의 수치와 예시는 제품 설계 목표이며 Planner 5D의 성능 측정값이 아니다.

| ID | 요구사항 | 확인 방법과 완료 기준 |
| - | - | - |
| F01 | 축척 설정 | 이미지의 400px 구간에 4,000mm를 입력하면 축척이 10mm/px로 저장되고 다시 열어도 유지 |
| F02 | 내측 치수 기준 | 4,000 × 3,000mm 방에 벽 두께 150mm를 적용해도 내측 공간 크기가 유지 |
| F03 | 구조 편집 무결성 | 직사각형 치수 변경 후 외곽이 닫혀 있고 자기 교차가 없음. 후속 L자 편집에도 같은 기준 적용. 불가능한 입력은 저장 전에 설명 |
| F04 | 문·창 위치 | 벽에 종속된 개구부가 벽 길이를 벗어나지 않음. 벽 변경 시 위치를 재검증 |
| F05 | 실제 가구 크기 | 2,000 × 900 × 850mm 소파가 입력한 크기로 표시. 90도 회전 시 평면 점유 폭·깊이가 바뀜 |
| F06 | 2D와 3D 일치 | 위치·회전·치수 변경이 두 화면에 반영되고 전환·재접속 후에도 동일 |
| F07 | 여유 거리 | 벽 내측면과 평행한 가구 사이에 600mm가 남는 예제에서 600mm를 표시 |
| F08 | 간섭 표시 | 알려진 겹침 예제와 문 회전 영역 예제에서 해당 대상이 강조됨. 경고를 눌러 이유 확인 |
| F09 | 배치안 분리 | B안의 가구 위치를 바꿔도 A안은 유지. 공통 방 구조 수정은 두 안에 반영되고 가구 간섭을 재검사 |
| F10 | 실행 취소 | 가구 삭제, 문 이동, 방 치수 변경을 각각 취소하고 직전 상태 복구 |
| F11 | 저장 및 복구 | 저장 완료 표시 후 브라우저를 종료하고 열었을 때 ID·치수·위치 보존. 미저장 상태는 완료로 표시하지 않음 |
| F12 | 내보내기 | 배치안 이름, 단위, 확인되지 않은 치수 표시가 있는 이미지를 생성 |

간섭 기능은 초기에는 평면의 가구 점유 영역과 문 회전 영역에 대한 기하학적 검사로 한정한다. 높이가 다른 물체의 배치에는 오탐이 있을 수 있다. 실제 보행 가능 여부는 선택한 구간의 거리로 판단하게 하며 자동으로 집 전체 동선을 판정하지 않는다. 통로 폭 기준은 사용자가 정할 수 있게 하고, 근거 없이 법정 기준이나 안전 기준으로 표현하지 않는다.

비기능 요구사항은 세 가지를 우선한다.

- **반응성:** 기준 기기와 예제 방을 정해 가구 30개 상태의 드래그·회전 시 프레임 시간을 기록한다. 30fps 이상을 초기 목표로 삼되 실측 후 확정한다.

- **데이터 보존:** 로컬 저장과 클라우드 저장을 구분한다. 자동 저장 완료 시점과 마지막 복구 가능 상태를 표시한다.

- **성능 조절:** 기본 모델과 제한된 텍스처로 시작하고, 편집 중에는 고품질 효과를 줄이며 필요할 때만 다시 렌더한다.

## 8 데이터 구조와 구현 방향

### 하나의 원본에서 2D와 3D 생성

2D 도면과 3D 장면을 따로 저장하면 치수와 위치가 어긋날 수 있다. 하나의 공간 데이터에서 두 화면을 생성한다. 내부 길이 단위는 mm로 통일하고 렌더러에 전달할 때만 좌표를 변환한다.

| 데이터 | 주요 필드와 역할 |
| - | - |
| Project | ID, 이름, 스키마 버전, 표시 단위, 수정 버전 |
| PlanSource | 원본 파일, 이미지 크기, 도면과 공간의 좌표 변환 |
| Calibration | 기준 두 점, 실제 길이, 축척, 추가 검증 길이 |
| Room | 내측 경계점, 벽 높이, 벽 두께, 치수 확인 상태 |
| Wall | 안정적인 ID, 연결된 경계점, 내측면 기준 |
| Opening | 벽 ID, 시작점으로부터 거리, 폭·높이, 창 하단 높이, 문 방향 |
| FurnitureItem | 사용자 가구 ID, 이름, 가로·세로·높이, 기본 모델 종류 |
| LayoutVariant | A/B ID, 이름, 공통 구조 참조, 가구 배치 목록 |
| FurniturePlacement | 배치 ID, 가구 ID, 위치, 회전, 잠금 상태 |
| Revision | 저장 버전, 저장 시각, 데이터 스냅샷 |

방 경계는 내측 공간을 기준으로 정의한다. 가구의 치수는 사용자가 확인한 실제 크기로 기록한다. 추정값과 실측값의 상태를 구분한다. 축척을 다시 설정할 때는 이미 검증한 치수를 자동 변경하지 않고 영향 범위를 확인하게 한다.

여러 방의 공유 벽 처리에는 별도 연결 규칙이 필요하다. P0에서는 방 하나를 대상으로 하며, P1에서 공유 벽을 하나의 객체로 관리하도록 확장한다.

### 권장 구현안

다음은 사용자 역량과 MVP 범위를 고려한 제안이다.

- 프런트엔드: React와 TypeScript. 2D 편집은 SVG 또는 Canvas, 3D는 Three.js.

- 기하 계산: 선택, 스냅, 거리, 회전, 간섭을 렌더링 코드에서 분리한 공통 모듈.

- 첫 저장: 브라우저의 로컬 저장소와 프로젝트 JSON 내보내기. 공간 데이터는 IndexedDB 등의 구조화된 저장소 사용.

- 서버 추가 시: Java Spring Boot 또는 Python FastAPI 중 익숙한 하나를 선택. 프로젝트·버전·구매 상태 관리.

- 데이터와 파일: PostgreSQL과 객체 저장소를 클라우드 저장 단계에서 추가.

- 3D 자산: 직접 만든 기본 형태부터 시작. 후속으로 사용 권한을 확인한 GLB 모델 추가.

Three.js의 [OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)는 카메라 회전·이동·확대 구현의 출발점이며, [GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)는 후속 모델 로딩에 활용할 수 있다. 라이브러리 도입만으로 도면 편집이나 치수 검증이 해결되는 것은 아니므로 기하 계산을 먼저 검증한다.

### 최소 저장 인터페이스

P0에는 서버가 필수는 아니다. P1의 서버 인터페이스는 다음 범위로 시작할 수 있다.

| 기능 | 설계안 |
| - | - |
| 프로젝트 생성과 조회 | 프로젝트 메타데이터와 최신 공간 스냅샷 |
| 저장 | 마지막으로 읽은 버전과 새 스냅샷 제출 |
| 충돌 | 서버 버전이 달라졌다면 덮어쓰지 않고 충돌 상태 반환 |
| 복구 | 저장된 이전 버전을 선택해 새 버전으로 복원 |
| 공유 | 읽기 전용 토큰 생성과 해제 |
| 접근 범위 | 기본 비공개. 링크 공유는 사용자가 명시적으로 생성 |

실시간 공동 편집보다 단일 사용자의 저장 충돌 처리를 먼저 완성한다.

## 9 개발 순서와 100시간 계획

주 20시간이면 누적 100시간은 약 5주다. 아래는 계획용 추정이며 기하 편집 난이도에 따라 조정한다.

| 단계 | 시간 | 완료할 결과 |
| - | - | - |
| 1 도면과 치수 | 20시간 | 실제 방 이미지, 축척 설정, 직사각형 모델 |
| 2 구조와 기본 가구 | 25시간 | 문·창, 가구 치수, 이동·회전, 실행 취소 |
| 3 3D와 저장 | 25시간 | 같은 모델의 3D 보기, 저장·복구, 카메라 초기화 |
| 4 비교와 거리 | 20시간 | A/B 전환, 간단한 거리·간섭, 이미지 내보내기 |
| 5 실제 사용 검증 | 10시간 | 본인 방 배치와 소수 사용자 시험, 주요 오류 수정 |

L자 편집은 기하 계산 검증을 마친 뒤 P1에서 추가한다. 일정이 밀리면 자동 간섭 범위부터 줄이고, 실제 치수·저장·2D/3D 일치를 유지한다.

첫 완료 기준은 “내 방의 실제 크기를 입력하고 구매 예정 가구를 배치해 두 안을 비교한 뒤, 저장하고 다음 날 이어서 수정할 수 있다”이다.

## 10 사용성 검증과 수익 가설

### 먼저 할 비교 시험

동일한 실제 방 자료로 Planner 5D와 새 앱을 비교한다. 아래 과제는 아직 수행하지 않은 시험 계획이다.

1. 4m × 3m 방, 문 하나, 창 하나를 만든다.

2. 소파·책상·수납장에 실제 상품 치수를 입력한다.

3. 가구와 벽 사이 거리를 확인한다.

4. 다른 배치를 만들고 같은 시점에서 비교한다.

5. 저장 후 종료하고 다시 연다.

6. 가족에게 결과를 보여주고 판단하기 어려운 지점을 기록한다.

플랫폼, 기기, 앱 버전, 무료·유료 상태, 성공 여부, 소요 시간, 잘못 선택한 횟수, 막힌 이유를 기록한다. 공개 후기만으로 차별화를 확정하지 않고 동일 과제에서의 차이로 판단한다.

첫 사용자 시험은 본인과 이사·인테리어를 준비하는 3명에서 5명으로 제안한다. 작은 표본에서는 실패 원인과 조작 문제를 찾고 시장 규모나 전환율을 추정하지 않는다.

### 수익 모델 가설

일회성 또는 짧은 기간의 인테리어 작업이라는 특성에 맞춰 프로젝트 단위 결제를 우선 검토한다.

| 구분 | 가설 |
| - | - |
| 무료 체험 | 방 하나, 기본 가구, 치수 편집, 3D 보기, 로컬 저장 |
| 유료 후보 | 여러 방, 클라우드 복구, 여러 배치안, 가족 공유, 결과 문서 |
| 가격 실험 | 프로젝트당 9,900원과 14,900원 비교 |
| 첫 매출 목표 | 14,900원 구매 7건이면 총매출 104,300원 |
| 확인할 비용 | 결제 수수료, 서버·파일 저장, 환불, 고객 지원, 세금 |

위 계산은 순수익이 아닌 총매출이다. 가격을 확정하기 전에 사용자가 결과물로 어떤 구매 결정을 내렸는지와 실제 지불 의사를 확인한다. 무료 기능만으로 문제를 충분히 해결한다면 유료 범위를 다시 설계한다.

## 11 다음 결정과 착수 자료

개발 전에 다음 다섯 항목을 확정한다.

- [ ] 최초 플랫폼: PC 편집 중심 웹인지, iPhone 편집 중심인지

- [ ] 입력 자료: 평면도 JPG·PNG인지 PDF인지, 실제 치수가 있는지

- [ ] 첫 대상: 거실 또는 방 하나인지, 집 전체가 반드시 필요한지

- [ ] 실제 상품 가구 5개에서 10개의 치수 확보

- [ ] 첫 사용자에게 전달할 결과물: 이미지, PDF, 공유 링크 중 우선순위

권장 착수 자료는 본인 집의 방 하나 도면, 서로 다른 방향의 실측 길이 두 개, 문·창 치수, 구매 예정 가구 목록이다. 이 자료로 F01부터 F06까지 먼저 구현하고, 실제로 배치가 가능한지 확인한 뒤 비교·간섭 기능을 추가한다.
